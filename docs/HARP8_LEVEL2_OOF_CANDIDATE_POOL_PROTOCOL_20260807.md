# HARP8 level-2 OOF candidate-pool protocol

Date: 2026-08-07

## Purpose

Candidate rows used to fit a level-2 full-router model must be generated by a
base HARP checkpoint that was not fit on those requests.  The row-selection
split and downstream level-2 role are therefore separate facts:

- `source_data_split` selects rows in `CompactHARPData`;
- `source_offline_split` records the immutable outer split of those requests;
- `level2_split` states whether the exported rows train or validate level 2.

An inner-validation source can consequently be a level-2 training pool.  It
must never be relabelled by overwriting its source provenance.

## Candidate-pool v2 contract

New exports use `harp8_candidate_pool_v2` and record:

```text
source_data_split
source_offline_split
level2_split
base_fold_id
base_fit_excluded
exported_request_ids_sha256
base_train_request_ids_sha256
base_train_request_ids
source_row_split_manifest
base_fit_split_manifest
base_train_request_ids_file
base_fit_overlap_count
```

`split` remains only as an explicitly tagged compatibility alias of
`level2_split`; it is not the row selector.  Source and base-fit split
manifests are separate, so an outer-validation proxy can use no source-row
manifest while still citing the inner manifest used to fit the base model.

Request sets are canonicalized as sorted unique decimal integers, one per
line with a final LF, then SHA-256 hashed.  The encoding identifier is
`sorted_unique_decimal_lf_v1`.  Canonical base-train IDs are embedded so a
loader can reproduce the hash and exclusion check after the original mount is
gone.

## Fail-closed rules

A level-2 training export requires all of the following:

1. `base_fit_excluded=true`;
2. a readable `harp8_inner_split_v1` base-fit manifest or explicit base-train
   request-ID file;
3. zero intersection between exported and base-fit request IDs;
4. a non-empty stable `base_fold_id`.

The full-router loader recomputes both request-set hashes and the exclusion
check from pool metadata.  The trainer must additionally reject any request
intersection between its level-2 train and validation pools.  Historical v1
validation pools remain readable.  V1 pools fail closed as level-2 training
unless a caller makes the explicit legacy API override; scientific new runs
must not use that override.

Test source rows are refused unless the export call explicitly enables sealed
test access.  Full-router development loaders refuse test-backed pools in all
cases.

## Operational patterns

Inner-heldout meta-training:

```text
--split-manifest INNER_SPLIT
--source-data-split validation
--source-offline-split train
--level2-split train
--base-fold-id inner-fold-0
--base-fit-excluded
--base-fit-split-manifest INNER_SPLIT
```

Outer-validation proxy using the same base checkpoint:

```text
# no --split-manifest: rows come from immutable outer validation
--source-data-split validation
--source-offline-split validation
--level2-split validation
--base-fold-id inner-fold-0
--base-fit-excluded
--base-fit-split-manifest INNER_SPLIT
```

The second command is precisely why source-row and base-fit manifests cannot
share one overloaded field.
